# 陶片拼接推演工作台（Sherd Stitch Workbench）

供考古工作室在浏览器中推演陶片（陶片/陶片残片）拼合关系的 Web 工作台。

- **Node.js（Express）+ SQLite（better-sqlite3）+ 浏览器 Canvas**，无前端构建步骤。
- 上传陶片照片、为每片标记**毫米比例尺**（图上像素长度 ↔ 真实毫米）。
- 以“接缝”记录两片之间的**旋转角 θ、平移 (tx, ty)**（单位毫米）与**接缝说明**。
- 画布按**已采纳接缝**自动拼出各**连通组**，显示每片位置及其所依据的**接缝链**；未连通陶片单独成卡显示。
- 新接缝形成环时，若推算位置与现有布局的偏差超过方案的**毫米容差**，**拒绝采纳**、给出**冲突接缝链**与偏差数值，**原布局保持不变**。
- **修订已采纳接缝**：可选任一接缝，提交修订后的旋转角、毫米平移与说明。先**预览**（按原接缝身份及排序重算陶片位姿与各闭合环残差、指出超容差接缝的冲突链，**不改动方案**），再基于当前版本**原子确认**；任一闭合环超差则整笔回滚（接缝、版本、布局均不变），接缝 ID 与排序始终不变，版本只递增一次。
- **撤销接缝即整体重算**连通组与位姿（布局从不持久化），不会沿用失效布局。
- **多人编辑乐观锁**：每个写请求须带 `Base-Version`；版本落后时返回 `409` 并在网页弹窗提示，绝不静默覆盖；页面还会每 10 秒轮询版本并提示他人更新。

## 运行方式

### 方式一：Docker Compose（推荐）

```bash
docker compose up --build -d
```

容器启动时即安装依赖、打开/创建 SQLite 并执行首次建表（`CREATE TABLE IF NOT EXISTS`），无需手工初始化。

浏览器访问：

```
http://localhost:8080
```

停止：

```bash
docker compose down          # 保留数据（命名卷 sherd-data）
docker compose down -v       # 同时删除数据库与上传图片
```

### 方式二：本机 Node.js

要求 Node.js ≥ 20。

```bash
npm install
npm start
```

默认访问 http://localhost:8080 ，数据库与图片位于 `./data/`（首次启动自动创建并建表）。

### 冒烟测试

```bash
npm test        # 即 node test/smoke.js
```

覆盖：建表就绪 → 建方案/上传/比例尺 → 接缝拼组与位姿传播 → 撤销断组重算 → 成环残差为 0 采纳 → 成环超差 422 拒绝且布局不变 → 过期版本 409 / 缺版本 428 →
接缝修订预览（只读、超差冲突链、不改状态）→ 超差确认 422 回滚（接缝/版本/布局不变）→
过期确认 409 / 缺头 428 / 参数 400 / 接缝 404 → 合法确认（ID 与排序不变、版本只 +1、读取布局与预览一致）。

## 使用说明

1. 首页**新建方案**，设定“闭合环毫米容差”（默认 2 mm，可随时在方案设置中修改）。
2. 进入方案，左侧**上传陶片照片**（图片在浏览器端自动压缩到最长边 2000px）。
3. 选中陶片 → **标记比例尺**：在照片上拖出一段对应已知长度的线段并填写毫米数（如 10 mm）。未标比例尺的陶片以占位尺寸单独显示，且不能参与接缝。
4. 点左侧 **新建接缝**：选择 A 片（参考、固定）与 B 片（移动对齐），在对齐窗口中
   拖动 B、用滚轮/输入框旋转 B，使断口吻合，并填写接缝说明；采纳即记录
   `p_B = R(θ)·p_A + (tx, ty)`（局部毫米坐标映射）。
5. 画布中：
   - **实线棕色**接缝为生成树接缝，决定布局；**橙色虚线**为成环接缝，仅用于闭合校验。
   - 陶片按毫米真实尺寸、按世界位姿绘制；右下角有毫米比例尺。
   - 点击陶片，右栏显示其毫米尺寸、世界位姿与“位置依据”接缝链（根片起的 `#接缝 → …`）。
   - 点击接缝编号可查看 θ/平移/说明、闭合残差并**撤销**。
6. 当新接缝形成环且闭合偏差超过容差时，会弹出拒绝框：显示偏差毫米数、角度差、
   冲突链（途经陶片与接缝及其说明），布局不发生任何变化。
7. **修订接缝**：在右栏接缝列表中点某条接缝的「修订」（或先点画布上的接缝编号再修订），
   输入修订后的 θ、tx、ty 与说明，点「预览重算」：
   - 画布切换为**预览态**（橙色提示条与边框，不落库），按**原接缝身份与采纳排序**重算
     各连通组陶片位姿；右栏「修订预览」面板列出参数变化、**位姿变化的陶片**、
     每个闭合环残差，超容差时给出该接缝的**冲突链**（点击可在画布高亮）。
   - 预览不改动方案，也不推进版本；可随时「取消预览」回到原布局。
   - 全部残差在容差内时「确认修订」可用。确认按当前 `Base-Version` **原子重算全部闭合环**：
     通过则接缝 ID 与排序不变、版本只 +1、读取布局与预览一致；任一残差超差则回滚并弹窗
     指出超差接缝与冲突链，**原接缝、版本与布局都不变**；若期间他人已更新方案（版本变化），
     确认返回 **409**，旧预览作废，需刷新后重新预览，不会套用旧预览。
8. 撤销任意接缝后，连通组立即重新划分、位姿由剩余接缝重新推导；原先连成一片的
   陶片可能分裂为多组或变为未连通片。

## 可配置项

均通过环境变量配置（见 `docker-compose.yml` 的 `environment`）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | HTTP 监听端口（容器内）。改宿主机访问端口请改 compose 的 `ports` 左侧，如 `"9090:8080"` |
| `DATA_DIR` | `./data`（本机）/ `/data`（容器） | 数据目录，存放 SQLite 与上传图片 |
| `DB_FILE` | `$DATA_DIR/workbench.db` | SQLite 数据库文件路径 |
| `UPLOAD_DIR` | `$DATA_DIR/uploads` | 陶片图片保存目录 |
| `MAX_UPLOAD_MB` | `20` | 单张照片上传大小上限（MB） |

方案级的**毫米容差**在网页“方案设置”中按方案独立配置，不是环境变量。

## HTTP API（含接缝修订示例）

所有写请求（POST/PATCH/DELETE，除修订预览外）须携带 `Base-Version` 头，值为当前方案
`version`；缺失返回 `428`，落后返回 `409`（含 `current_version`/`your_version`）。
其余常用接口：`GET /api/projects/:id` 取方案（含现算 `layout`）、
`POST /api/projects/:id/seams` 新建接缝、`DELETE /api/seams/:id` 撤销接缝。

### 1) 修订预览（只读，不需要 Base-Version，不改状态）

```bash
curl -s -X POST http://localhost:8080/api/seams/12/revision-preview \
  -H 'Content-Type: application/json' \
  -d '{"theta_deg": 12.5, "tx": -30.2, "ty": 1.0, "join_note": "口沿对齐角度复核"}'
```

返回“按原接缝身份（#12）及采纳排序重算”的完整方案视图（`project` / `sherds` /
`seams`(含修订后接缝) / `layout`），并带：

- `revised_seam_id`、`revised_seam`、`original_seam`
- `acceptable`：全部闭合环残差是否都 ≤ `tolerance_mm`
- `violations[]`：每条超容差成环接缝的 `seam_id`、`distance_mm`、`rotation_deg`、
  `tolerance_mm` 与 `conflict_chain`（`sherds` 路径 + 生成树上的 `seams` 路径，含说明）

### 2) 确认修订（写，必须 Base-Version，原子重算全部闭合环）

```bash
curl -s -X PATCH http://localhost:8080/api/seams/12 \
  -H 'Content-Type: application/json' \
  -H 'Base-Version: 18' \
  -d '{"theta_deg": 12.5, "tx": -30.2, "ty": 1.0, "join_note": "口沿对齐角度复核"}'
```

- `200`：修订生效。接缝 **ID 与排序不变**，方案版本只递增一次，返回与
  `GET /api/projects/:id` 相同的方案负载，其 `layout` 与预览一致。
- `422`：在当前版本上原子重算后有闭合环超差 → **整笔回滚**，接缝、版本、布局均不变。
  响应 `error.reason = "revision_cycle_tolerance_exceeded"`，含 `violations`（超差接缝 +
  冲突链）与 `preview_layout`（仅供展示“若采纳会得到的布局”，库中并未改变）。
- `409`：`Base-Version` 落后（他人已更新），不套用旧预览；`428`：缺少头。
- `400`：参数无效（θ 需为 -360…360 的数字，tx/ty 为 -100000…100000 的数字，
  说明最多 2000 字）；`404`：接缝不存在。以上均不改变任何状态。

> 预览与确认共用同一套“按身份与排序重算”逻辑，因此确认通过后的读取布局必然等于预览布局。

## 网页访问端口

- 默认：**http://localhost:8080**
- Docker 下在 `docker-compose.yml` 修改端口映射；本机运行用 `PORT=9090 npm start`。

## 数据模型

- `projects`：方案（名称、毫米容差、乐观锁 `version`）。
- `sherds`：陶片（图片文件、图像像素宽高、比例尺 `scale_px`/`scale_mm`）。
- `seams`：有向接缝 `from_id → to_id`，`theta_deg / tx / ty`（把 from 局部毫米坐标
  映射到 to 局部毫米坐标），`join_note` 接缝说明。接缝可被**修订**（仅改这四列），
  修订不改变接缝 `id`、采纳排序与两端陶片。
- 每次写事务都会把 `projects.version + 1`；布局（连通组、位姿）**只在读取时现算**，
  不入库，因此撤销/修订后天然不会残留旧位置。修订确认在同一事务内重算全部闭合环，
  任一残差超差即回滚，连这次的 `version + 1` 也不会发生。
